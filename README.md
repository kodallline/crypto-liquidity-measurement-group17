# How to Measure the Liquidity of Cryptocurrencies? | Group 17

Research seminar project (HSE, Data Analysis in Finance) based on Brauneis, Mestel, Riordan and Theissen (2021), *How to Measure the Liquidity of Cryptocurrency Markets?*, *Journal of Banking & Finance*.
We rebuild the paper's liquidity benchmarks and proxies on **our own Tardis.dev data**, not on the authors' dataset (we asked the authors for it and got no reply).

## What we did

- **Data:** Bitfinex, Bitstamp and Coinbase, BTC/USD and ETH/USD, the first day of each month, Jun–Dec 2019. That gives 1,008 market-hours, of which 807 are valid.
- **Benchmarks:** quoted spread, effective spread, price impact and a 25-level roundtrip cost.
- **Proxies:** the paper's eight low-frequency proxies (TX, $Vol, Amihud, Roll, Kyle, Corwin–Schultz, Abdi–Ranaldo).
- **Comparison:** we repeat the paper's tests (correlations, level errors, venue rankings, market regimes).
- **Our extension:** volatility-controlled correlations, a date-block bootstrap, a zero baseline for level errors, and calibration on early dates tested on later dates.

## Main results

- Abdi–Ranaldo (AR) is again the best proxy for the quoted and effective spreads and the roundtrip cost (BTC: 0.75 / 0.80 / 0.68 vs 0.76 / 0.84 / 0.71 in the paper).
- After removing volatility, AR still tracks the spreads (partial correlation 0.41–0.67). It no longer tracks price impact.
- Amihud's "accurate" levels are the same as always predicting zero.
- Only 7 days of data, so the results are indicative.

## How to run (Google Colab, about 1 minute)

1. Download the notebook and the 8 files from `data/`.
2. Open the notebook in [Google Colab](https://colab.research.google.com/).
3. Upload the 8 files to `/content` (Files → Upload). Do not rename them.
4. Keep `FAST_MODE = True` and click **Runtime → Run all**.

To run locally in Jupyter, keep the files in `data/` next to the notebook.
`FAST_MODE = False` downloads the raw Tardis.dev files and recomputes everything. This takes several hours.

## Data

The `data/` folder holds prepared minute and hourly tables built from Tardis.dev recordings. The raw Tardis.dev files are not included. File descriptions are in `data/README.md`.
